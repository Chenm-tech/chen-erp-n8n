# כללי מע"מ וחשבוניות שהמערכת מיישמת

המקור המלא: [`policies/06-israeli-tax-invoice-rules.md`](../policies/06-israeli-tax-invoice-rules.md). כאן רק מה ש-WF1 ו-WF8 עושים בפועל.

## שיעור המע"מ

| תקופה | שיעור |
|---|---|
| עד 31.12.2024 | 17% |
| מ-1.1.2025 | 18% |

WF1 בוחר את השיעור לפי תאריך `Created` של החשבונית (צומת *Compute VAT*):

```
rate      = Created >= 2025-01-01 ? 0.18 : 0.17
VatAmount = round(Amount * rate, 2)
Total     = round(Amount + VatAmount, 2)
```

הכל מספרים (לא מחרוזות), אחרת `Amount + VatAmount` היה מחבר טקסט.

## מספור עוקב

- פורמט `INV-0001`. WF1 שולף את המספר הגבוה ביותר הקיים, מוסיף 1, ומרפד ל-4 ספרות.
- מספרים לא מדלגים ולא חוזרים, כנדרש מרציפות חשבוניות מס.
- מגבלה ידועה: שתי חשבוניות שנוצרו באותה דקת פולינג עלולות לקבל אותו מספר. פתרון אפשרי (לא מומש בכוונה): טור Autonumber ב-Airtable או נעילה ב-n8n.

## מה חייבת לכלול חשבונית מס, ואיפה זה בתבנית (WF8)

| דרישה | בתבנית |
|---|---|
| שם העסק, מספר עוסק מורשה, כתובת | כותרת |
| המילים "חשבונית מס" ו"מקור" | כותרת |
| מספר עוקב | `InvoiceNumber` |
| תאריך הפקה | `$now` באזור זמן ישראל |
| פרטי הלקוח | `CustomerId` |
| פירוט, סכום לפני מע"מ, שיעור וסכום המע"מ, סה"כ | טבלה |

## סטטוסים

| Status | משמעות |
|---|---|
| (ריק) | נוצרה, טרם עובדה |
| Ready | עברה אימות, יש מספר ומע"מ, ממתינה להפקה |
| Issued | המסמך הופק ונמצא בדרייב, טרם שולמה |
| Paid | שולמה (סימון ידני באפליקציה) |
| Invalid | סכום 0 או בלי לקוח. לא נכנסת למספור |

סוכן המנהל מחשב: הכנסות = Issued + Paid; חוב לקוחות = Issued; התקבל בפועל = Paid.
